# nastest — ARM-NAS 极限性能测试框架

针对 ARM 平台 NAS(主线设备:fnOS RK3576)的**极限性能基准测试框架**,
依据 [`docs/ARM-NAS-极限性能测试方案.md`](docs/ARM-NAS-极限性能测试方案.md) 实现:
覆盖 **峰值 / 持续(浸泡)/ 极限容量** 三个层次,回答方案的四个核心问题
(瓶颈在哪一层、长跑是否衰减、并发拐点、加密开销),并按方案 §8 输出
优/良/及格/差 评级与 ARM 红旗检测。

## 仓库结构

```
docs/            测试方案(§3 测试纪律 / §5 维度 / §7 报告 / §8 评级)
nastest/         测试框架本体(FastAPI + SQLite + Web 界面),详见 nastest/README.md
```

## 特性一览

- **78 条用例(S0~S9)**:环境基线 / CPU / 内存 / 存储(fio 矩阵+元数据+裸盘基线)/
  网络(iperf3)/ 协议(SMB/NFS/FTP/WebDAV/rsync)/ 并发扩展 / 应用 / 浸泡稳定性 / 功耗;
- **自动化优先**:71 条可自动执行,设备端(SSH)与本机客户端双端驱动,
  每条命令完整日志落盘,指标存 SQLite,原始输出(fio JSON 等)存证据目录;
- **单用例可点击执行 + 域顺序运行**:任意用例随时单独重跑;每个域可一键依次执行;
- **S3 按 RAID 子组运行**:存储子系统分 basic / RAID0 / RAID1 / RAID5 / RAID6 / RAID10
  六组,人工切换阵列后运行对应组,执行前自动校验阵列级别(不符拒跑),
  报告按已测 RAID 组逐级出子表对比;
- **存储卷自动探测**:卷路径可留空,自动探测数据卷并校验挂载点有效性;
- **测试纪律(方案 §3.3)**:≥N 轮中位数、方差 >10% 标记、热身、direct=1、
  测试文件大于内存、governor/aes-ce 检查;
- **浸泡实时监控**:后台压测 + 周期采样(温度/频率/CPU/IOPS/带宽)实时查看;
- **报告**:基线卡 → 四问答 → 各维度表(附测试方法/底层原理/命令)→ §8 评级 →
  红旗清单,Markdown 下载 + HTML 在线查看。

## 快速开始

```bash
cd nastest
pip install -r requirements.txt     # fastapi uvicorn jinja2 paramiko smbprotocol httpx
python -m app.main                  # 打开 http://127.0.0.1:8080
```

流程:新建任务(设备 IP/SSH、存储卷可留空自动探测)→ 环境检查(自动装缺失依赖)→
开始自动测试 → 人工阶段按指导提交判定 → 生成报告。

## 数据与安全

- `nastest/data/` 为运行时数据(数据库 + 证据目录),已在 `.gitignore` 中排除 ——
  数据库内含明文密码(仅本地测试台使用),**勿提交、勿外传**;
- API 回显配置时 `ssh_pass / smb_pass / local_sudo_pass` 均掩码为 `***`;
- 高危用例(满容量衰减 / RAID 重建 / 断电恢复)需输入用例编号确认后才执行。
